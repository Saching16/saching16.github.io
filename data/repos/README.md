# Research Repo Snapshots

This folder holds generated copies of the public research repositories the Digital Twin can talk about. The chat API reads the committed files. It does not call GitHub.

## Files

- `config.mjs`: the repo list. Another public repo is added by putting another entry here.
- `manifest.json`: generated record of each included branch and its commit ID from the last sync. Do not edit by hand.
- `<slug>/snapshot.json`: generated by `npm run sync-repos`. It stores file contents, who wrote each file, commit logs, and diffs from the default branch. Do not edit by hand.
- `<slug>/overview.md`: generated by `npm run build-repo-overview` when a snapshot branch commit changed. `npm run sync-rag` adds it to the chatbot sources. Do not edit by hand.

`npm run sync-repos` prints `unchanged` and leaves the snapshot in place when no branch commit was added, updated, or deleted. `npm run build-repo-overview` prints `unchanged` and skips the model when the overview already matches those commits.

## Excluding a branch

`excludeBranches` in `config.mjs` drops matching branch names before they are snapshotted. Patterns need `**` when the name has more than one slash. The current entry ignores `cursor/**` and `dependabot/**`, so a branch named `cursor/test` is left out. Every other branch is included.

If the remaining branches exceed `maxBranches`, the sync fails and prints the limit. Add an exclude pattern, then run the sync again. The snapshot does not grow past that limit on its own.

## Refreshing locally

From a checkout of this website, with `git` available:

```bash
npm run sync-repos
npm run build-repo-overview
npm run sync-rag
```

`npm run sync-repos` clones each repo in `config.mjs`. No GitHub token is required while those repos stay public. `npm run build-repo-overview` needs `OPENAI_API_KEY` in `.env` only when a branch commit changed. It calls `gpt-4.1` once for that repo, clips long sources, and waits 65 seconds before a validation retry so the request stays under the account limit of 30,000 tokens per minute.

The weekly workflow in `.github/workflows/weekly-rag-refresh.yml` runs these commands after the Google Drive fetch. When a snapshot, overview, or Drive source changed, it opens a pull request titled "Update chatbot sources". A failure in `npm run sync-repos` or `npm run build-repo-overview` fails the workflow, so it does not open a pull request that looks successful.

A published file whose name contains `key`, such as `notes/api_key.txt`, is not covered by `exclude` and makes `npm run sync-repos` exit with an error. `.env`, `.env.*`, and `*.pem` are left out of the snapshot with a warning. Tokens in an ordinary source file are replaced with `[redacted]` and the sync continues.

See [data/rag/README.md](../rag/README.md) for the Drive half of the same workflow.
